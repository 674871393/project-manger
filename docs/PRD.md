# PRD — 前端项目管理器（Frontend Project Manager）

| 项 | 内容 |
|---|---|
| 产品定位 | 本地桌面工具，统一管理所有前端项目的启动、停止与运行状态 |
| 技术栈 | React + Tauri 2 + shadcn/ui（+ TypeScript + Tailwind CSS） |
| 目标平台 | Windows 11（当前唯一目标平台） |
| 使用者 | 单人（开发者本人），本地运行，无多用户/联网需求 |
| 文档版本 | v0.1（2026-09-10） |

---

## 1. 背景与目标

### 1.1 背景

手上有多个前端项目分散在不同目录（如 `d:\project` 下）。日常痛点：

- 每次开发都要手动开终端、`cd` 到项目目录、敲启动命令，重复且繁琐；
- 多个项目同时跑时记不清哪个端口对应哪个项目；
- 想停掉某个项目时，要去找对应的终端窗口按 Ctrl+C，或去任务管理器杀 node 进程；
- 不记得某个项目当前在哪个分支上。

### 1.2 目标

做一个本地桌面应用，把「所有前端项目」收进一张列表：

- **一键启动 / 一键停止 / 一键重启**某个项目；
- 一眼看到每个项目的**运行状态**（运行中 / 已停止 / 异常）、**运行地址**（可点击打开）、**当前分支**；
- 随时查看某个项目的**实时日志**。

### 1.3 非目标（本期不做）

- 不做项目管理意义上的功能（任务、看板、排期等）；
- 不做代码编辑、Git 高级操作（commit / pull / push）；
- 不做依赖安装、构建发布流水线；
- 不做远程/团队协作，不联网同步；
- 不做非前端项目的通用进程管理。

## 2. 用户与使用场景

**用户画像**：前端开发者，Windows 11，本机有多个前端项目（Vite / Next.js / Vue CLI / webpack 等各类脚手架产物）。

**核心场景**：

| # | 场景 | 期望结果 |
|---|---|---|
| S1 | 早上开工，想同时起 2-3 个项目 | 在列表里逐个点「启动」，看到状态变绿、地址可点 |
| S2 | 5173 端口被占，不确定是哪个项目 | 在列表里看「运行地址」列，直接定位 |
| S3 | 某项目热更新卡死 / 日志报错 | 点「日志」看实时输出，或点「重启」 |
| S4 | 下班 / 切换任务，清理所有进程 | 逐个点「停止」，或关闭应用时全部自动停止 |
| S5 | 想确认某项目当前分支是否正确 | 看「当前分支」列 |

## 3. 功能需求

优先级说明：**P0** = 第一版必须有；**P1** = 第一版尽量有；**P2** = 后续迭代。

### FR-1 项目录入与管理（P0）

列表的数据来源，必须有增删改，否则列表无从谈起。

- **添加项目**：点击工具栏「添加项目」按钮，弹出 Dialog，选择本地文件夹（Tauri 文件夹选择器）；
- **自动识别**：选定文件夹后读取 `package.json`，自动带出：
  - 项目名称（`package.json` 的 `name`，默认取文件夹名）；
  - 包管理器（根据锁文件推断：`pnpm-lock.yaml` → pnpm，`yarn.lock` → yarn，`bun.lockb` → bun，`package-lock.json` → npm，默认 npm）；
  - 启动脚本（优先 `dev`，其次 `start`，允许手动改）；
  - 框架类型（根据 dependencies 推断 vite / next / nuxt / webpack，仅作展示标签用）；
- **编辑**：可修改名称、路径、包管理器、启动脚本；
- **删除**：从列表移除（仅移除记录，不删磁盘文件）；若项目正在运行，需先停止或二次确认；
- **持久化**：项目列表保存在本地（Tauri `appDataDir` 下的 JSON 文件），重启应用后仍在。

### FR-2 项目列表（P0）

主界面即一张表格（shadcn/ui Table），列为：**项目名称 | 运行地址 | 运行状态 | 当前分支 | 操作**。

- **项目名称**：显示名称 + 框架标签（小 Badge），悬停显示本地路径；
- **运行地址**：
  - 运行中：显示 `http://localhost:5173` 样式的可点击链接，点击用系统默认浏览器打开；
  - 已停止：显示配置的预期端口（灰色）或不显示；
- **运行状态**：Badge 展示四种状态：
  - `stopped` 已停止（灰色）
  - `starting` 启动中（黄色，转圈图标）
  - `running` 运行中（绿色圆点）
  - `error` 异常退出（红色，悬停显示退出码）
- **当前分支**：显示分支名（如 `feat/login`）；非 Git 目录显示 `-`；
- **操作**：见 FR-3、FR-4。

### FR-3 启动 / 停止 / 重启（P0）

- **启动**：
  - 在项目目录下以配置的包管理器执行启动脚本（如 `pnpm dev`）；
  - 按钮变为「停止」；状态先进入 `starting`，检测到服务就绪后变 `running`；
  - 若该项目已在运行，「启动」按钮置灰，防止重复启动；
- **停止**：
  - 结束该项目对应的**整个进程树**（详见 6.3，Windows 关键点）；
  - 进程退出后状态回到 `stopped`，释放端口；
- **重启**：先执行停止逻辑，确认退出后再执行启动逻辑（不是并行发两份命令）；
- **状态同步**：进程意外退出（崩溃、被外部杀死）时，列表状态要自动更新为 `error`，并保留退出码。

### FR-4 日志（P0）

- 点击操作列「日志」，右侧滑出 Sheet（抽屉）展示该项目 stdout + stderr 合并的实时日志；
- 日志按行流式追加，自动滚动到底部；用户向上滚动时暂停自动跟随，并提供「回到最新」按钮；
- 功能：复制全部、清空当前视图、按关键字过滤（P1）；
- 缓冲上限：每个项目内存中保留最近 2000 行，超出丢弃最旧的（防止长跑项目内存膨胀）；
- stderr 行以红色/警告色渲染，便于 spotting 报错；
- 打开日志时若项目未运行，显示历史日志（上次会话）+ 提示「项目未运行」。

### FR-5 运行地址与端口检测（P0）

- **自动解析**：从日志输出中用正则匹配本地地址，如 `http://localhost:(\d+)`、`http://127.0.0.1:(\d+)`（兼容 Vite 的 `Local:   http://localhost:5173/`、webpack 的 `App running at:`、Next 的 `- Local:  http://localhost:3000`）；
- 解析成功后更新该行的「运行地址」，并触发一次可达性探测（TCP 连通即可）确认 `running`；
- **手动兜底**：项目编辑里允许手动填端口（解析不出的脚手架用）；
- 端口冲突提示（P1）：启动前检测目标端口是否已被占用，占用时弹 toast 警告。

### FR-6 当前分支显示（P1）

- 读取项目目录下 `.git/HEAD` 解析出分支名（不 spawn git 进程，快且无依赖）；
- 刷新时机：列表手动刷新按钮、启动/停止时、定时轮询（如 30s，P2）；
- 展示 `main` / `feat-xxx`；有未提交变更时在分支旁加一个小圆点提示（P2）。

### FR-7 设置（P1）

- **项目级**：包管理器、启动脚本、环境变量（如 `PORT=3001`）、手动端口；
- **全局**（P2）：日志行数上限、默认包管理器、关闭应用时是否自动停止所有项目。

### FR-8 批量与其他（P2）

- 全部停止 / 全部重启；
- 按名称搜索过滤列表；
- 最小化到系统托盘（后台保活项目进程）；
- 一个项目支持多个脚本（dev + mock server）；
- 一键 `npm install`。

## 4. 交互与界面设计

### 4.1 布局

```
┌──────────────────────────────────────────────────────┐
│ ◆ 前端项目管理器        [搜索框] [+ 添加项目] [⟳ 刷新] │
├──────────────────────────────────────────────────────┤
│ 项目名称        │ 运行地址             │ 状态   │ 分支      │ 操作                    │
├────────────────┼──────────────────────┼────────┼───────────┼─────────────────────────┤
│ admin [vite]   │ http://localhost:5173 │ ● 运行中│ feat/login │ [日志] [停止] [重启]     │
│ h5-app [next]  │ http://localhost:3000 │ ○ 已停止│ main      │ [日志] [启动] [重启]     │
│ old-crm [wp]   │ —                     │ ✕ 异常 │ develop   │ [日志] [启动] [重启]     │
└──────────────────────────────────────────────────────┘
                              └─ 点「日志」右侧滑出 Sheet，实时滚动输出
```

### 4.2 组件选型（shadcn/ui）

| 界面元素 | 组件 |
|---|---|
| 项目表格 | `Table`（列固定，操作列右对齐） |
| 状态 | `Badge`（四种 variant）+ lucide 图标（`CircleDot` / `Circle` / `Loader2` 旋转 / `CircleX`） |
| 操作按钮 | `Button` variant=`ghost` size=`icon`，图标 `ScrollText` / `Play` / `Square` / `RotateCcw`，悬停 tooltip |
| 日志抽屉 | `Sheet`（side=right，宽度约 50%）内部等宽字体滚动区 |
| 添加/编辑项目 | `Dialog` + `Form`（文件夹选择用 Tauri dialog） |
| 通知 | `Sonner`（toast：启动失败、端口冲突、删除确认等） |
| 删除确认 | `AlertDialog` |

### 4.3 关键交互流

**启动流程**：
1. 点击「启动」→ 按钮进入 loading，状态 `starting`；
2. 后端 spawn 进程，开始转发日志事件；
3. 前端从日志解析出端口 → 探测连通 → 状态 `running`，地址列变为可点链接；
4. 10s 内未解析到端口但进程仍存活：保持 `running`（按进程存活判断），地址显示「未识别」；
5. 进程启动即退出（脚本报错）：状态 `error`，自动弹出日志抽屉。

**停止流程**：
1. 点击「停止」→ 按钮 loading；
2. 后端 kill 进程树 → 收到退出事件 → 状态 `stopped`；
3. 3s 未退出：升级为强制 kill（`taskkill /T /F`），toast 提示「已强制结束」。

## 5. 数据模型

```ts
// 持久化到 appDataDir/projects.json
interface Project {
  id: string            // uuid
  name: string          // 展示名
  path: string          // 项目绝对路径
  packageManager: 'npm' | 'pnpm' | 'yarn' | 'bun'
  script: string        // 启动脚本名，默认 'dev'
  manualPort?: number   // 手动指定端口（解析失败时兜底）
  env?: Record<string, string>
  framework?: 'vite' | 'next' | 'nuxt' | 'webpack' | 'other'  // 仅展示用
  createdAt: number
}

// 运行时状态（内存，不持久化；随进程事件更新）
interface RuntimeState {
  projectId: string
  status: 'stopped' | 'starting' | 'running' | 'error'
  pid?: number
  url?: string          // 解析出的运行地址
  startedAt?: number
  exitCode?: number     // error 时展示
}
```

## 6. 技术方案

### 6.1 总体架构

- **前端**：React + TypeScript + Vite + Tailwind + shadcn/ui；状态管理 zustand（两个 store：`projectsStore` 持久化数据、`runtimeStore` 运行时状态与日志缓冲）；
- **后端**：Tauri 2（Rust）承担进程生命周期、文件读写、Git 分支读取、端口探测；
- **通信**：`invoke`（命令）用于请求-响应（添加项目、读 package.json、读分支）；`emit`/`listen`（事件）用于日志流与状态推送。

### 6.2 依赖的 Tauri 插件

| 插件 | 用途 |
|---|---|
| `@tauri-apps/plugin-shell` | spawn 开发服务器进程、事件转发 stdout/stderr |
| `@tauri-apps/plugin-dialog` | 文件夹选择器 |
| `@tauri-apps/plugin-fs` | 读 `package.json`、`.git/HEAD`，写 `projects.json` |
| `@tauri-apps/plugin-opener` | 用系统浏览器打开运行地址 |

### 6.3 进程管理（本项目最大的技术风险点 ⚠️）

Windows 上 `npm run dev` 的真实进程是一棵树：`npm.cmd (cmd.exe)` → `node (npm)` → `node (vite/next)`。**只 kill 最外层进程会留下孤儿 node 进程继续占着端口**——这是这类工具最常见的坑，方案必须正面处理：

- 停止时执行 `taskkill /PID <pid> /T /F`（`/T` 杀整棵树，`/F` 强制）；
- 因此 spawn 与 kill 都建议放在 **Rust 侧**统一管理（Rust 持有所有 `Child` 句柄的 pid 表），而不是用 JS 侧的 shell 插件 API 散落管理；
- **应用退出清理**：监听 Tauri 退出事件（`RunEvent::ExitRequested` / 窗口关闭），对所有运行中项目执行 kill，确保关掉工具不留下任何孤儿进程（验收标准里有专项测试）。

### 6.4 事件流

```
Rust spawn ──(log-line 事件, 含 projectId)──▶ 前端日志缓冲 + 端口正则解析
        └──(process-exit 事件, 含 code)──▶ runtimeStore 更新状态
前端 invoke:start(projectId) / stop(projectId) ──▶ Rust 命令
```

## 7. 边界与异常场景

| 场景 | 预期行为 |
|---|---|
| 启动脚本报错立即退出 | 状态 `error`，自动弹出日志抽屉，展示退出码 |
| 端口被占用（脚手架自动换端口） | 以日志解析出的实际端口为准，地址更新 |
| 端口被占用（脚手架直接失败） | 走 error 流程，日志可见原因 |
| 项目文件夹被删除/移动 | 列表仍显示，启动时报错 toast，编辑可改路径 |
| `package.json` 缺失 | 添加时校验拒绝，提示「不是有效的前端项目」 |
| 应用启动时上次有项目在跑（异常退出残留） | 可选：启动时检测并提示清理孤儿进程（P1） |
| 日志爆炸（如 watch 模式高频输出） | 2000 行环形缓冲，UI 批量渲染（虚拟滚动，P1） |
| 同一项目重复点击启动 | 按钮置灰 + runtimeStore 幂等保护 |

## 8. 非功能需求

- **可靠性（最高优先级）**：任何路径下（正常停止、应用崩溃、系统重启）不允许留下孤儿 node 进程 / 被占端口；进程真实状态与 UI 展示状态必须一致；
- **性能**：点击启动到命令下发 < 1s；日志事件到 UI 渲染延迟 < 100ms；列表加载 < 500ms（20 个项目以内）；
- **安全**：Tauri shell 权能白名单严格限定（只允许配置的包管理器命令），不做通用终端；
- **数据**：全部本地（appDataDir），无任何网络上报；
- **可维护性**：前端 TS 全量类型，Rust 侧进程管理集中在一个模块。

## 9. 验收标准（第一版）

1. 添加一个 Vite 项目，点「启动」→ 15s 内状态变 `running`，地址可点击且浏览器能打开页面；
2. 点「停止」→ 状态变 `stopped`，`netstat` 确认端口已释放，任务管理器无残留 node 进程；
3. 点「重启」→ 完整走一遍停止 + 启动；
4. 人为在项目里制造脚本报错 → 状态变 `error` 并自动弹出日志；
5. 日志抽屉实时滚动、可复制、可清空，stderr 有颜色区分；
6. 外部手动杀掉某项目进程 → 列表状态 3s 内自动变为 `error`；
7. 同时运行 3 个项目，关闭应用 → 任务管理器确认 0 个残留 node 进程；
8. 重启应用 → 项目列表完整保留；
9. 非 Git 目录项目分支列显示 `-`，Git 项目显示正确分支名。

## 11. 开放问题（需要你确认）

1. **项目录入方式**：手动逐个添加（本 PRD 默认方案），还是额外提供「扫描 `d:\project` 一键批量导入子文件夹」？（后者可作 P1）
2. **日志形态**：右侧抽屉（默认），还是 VS Code 风格的底部面板？
3. **应用关闭行为**：默认「关闭即停止所有项目」还是「最小化到托盘、项目继续跑」？（本 PRD 默认前者，托盘作 P2）
4. 是否需要中文界面 only，还是中英双语？（默认中文 only）
