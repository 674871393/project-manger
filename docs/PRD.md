# PRD — 前端项目管理器（Frontend Project Manager）

| 项 | 内容 |
|---|---|
| 产品定位 | 本地桌面工具，统一管理所有前端项目的启动、停止与运行状态 |
| 技术栈 | React + Tauri 2 + shadcn/ui（+ TypeScript + Tailwind CSS） |
| 目标平台 | Windows 11（当前唯一目标平台） |
| 使用者 | 单人（开发者本人），本地运行，无多用户/联网需求 |
| 文档版本 | v0.2（2026-09-11） |

> **v0.2 修订说明**：初版 PRD（v0.1，2026-09-10）规划的 M1–M4 已全部交付，且实际实现范围超出原 PRD（单实例、托盘、批量操作、扫描导入等）。本文档补记全部已实现能力，并规划下一阶段（v0.2 迭代）的功能范围。
>
> **状态图例**：✅ 已实现　🚧 部分实现　⏳ 待开发

## 1. 背景与目标

### 1.1 背景

手上有多个前端项目分散在不同目录（如 `d:\project` 下）。日常痛点：

- 每次开发都要手动开终端、`cd` 到项目目录、敲启动命令，重复且繁琐；
- 多个项目同时跑时记不清哪个端口对应哪个项目；
- 想停掉某个项目时，要去找对应的终端窗口按 Ctrl+C，或去任务管理器杀 node 进程；
- 不记得某个项目当前在哪个分支上。

### 1.2 目标

做一个本地桌面应用，把「所有前端项目」收进一张列表：

- **一键启动 / 一键停止 / 一键重启**某个项目；
- 一眼看到每个项目的**运行状态**（运行中 / 已停止 / 异常）、**运行地址**（可点击打开）、**当前分支**；
- 随时查看某个项目的**实时日志**。

v0.2 阶段在「管家」定位上进一步延伸：不只管「启停」，还管**依赖安装、多脚本、进程资源、端口归属**等日常运维动作。

### 1.3 非目标（持续有效）

- 不做项目管理意义上的功能（任务、看板、排期等）；
- 不做代码编辑、Git 高级操作（commit / pull / push）；
- 不做 CI/CD 与远程发布（FR-20 仅覆盖本机一键打包：选择构建用 Node → 切分支 → 升版本 → build → zip）；
- 不做远程/团队协作，不联网同步；
- 不做非前端项目的通用进程管理。

## 3. 功能需求 — 已实现部分（v0.1 范围）

### FR-1 项目录入与管理 ✅

- **添加项目**：工具栏「添加项目」→ Dialog → Tauri 文件夹选择器；
- **自动识别**（`inspect_project` 命令）：
  - 项目名称（`package.json` 的 `name`，回退文件夹名）；
  - 包管理器（锁文件推断：`pnpm-lock.yaml` → pnpm，`yarn.lock` → yarn，`bun.lockb` / `bun.lock` → bun，`package-lock.json` → npm，默认 npm）；
  - 启动脚本（优先 `dev`，其次 `start`，允许手动改）；
  - 框架类型（dependencies 推断 next / nuxt / vite / webpack / other，仅展示标签用）；
- **编辑**：名称、路径、包管理器、启动脚本、环境变量（KV 行编辑）、手动端口兜底；
- **删除**：AlertDialog 二次确认；运行中项目删除有提示；
- **持久化**：`appDataDir/projects.json`，临时文件 + 原子替换写入防损坏。

### FR-2 项目列表 ✅

- 表格列：**项目名称（+ 框架标签）｜ 运行地址 ｜ 运行状态 ｜ 当前分支 ｜ 操作**；
- 运行地址可点击（系统默认浏览器打开）；已停止显示灰化地址或 `—`；
- 状态包括「已停止」「启动中」「进程已启动」「服务已就绪」「异常」；
- 项目名称悬停显示本地路径。

### FR-3 启动 / 停止 / 重启 ✅

- 启动：Rust 侧 spawn 成功标为 `running`；收到本次开发日志或配置了手动端口时，校验监听归属并探测，成功后标为 `ready`；
- 停止：`taskkill /PID <pid> /T /F` 终止进程树，后端确认退出后返回；超时或失败时提示用户；
- 重启：严格「先停、确认退出、再启」，不并行发两份命令；
- 状态同步：exit waiter + 宽限标记区分「主动停止」与「崩溃/被外部杀」；异常退出 → `error` + 保留退出码 + 自动弹出日志抽屉；
- **应用退出清理**：`RunEvent::ExitRequested` → `stop_all`，关工具不留孤儿进程；
- **崩溃残留清理**：启动时按 `running-pids.json` 检测并清理上次异常退出残留的孤儿进程（toast 提示）。

### FR-4 日志 🚧

已实现：

- 右侧 Sheet 抽屉，stdout + stderr 合并流式追加；
- 自动跟随 / 向上滚动暂停跟随 / 「回到最新」按钮；
- 复制全部、清空当前视图；
- stderr 行红色区分；ANSI 转义序列剥离；
- 每项目 2000 行内存环形缓冲。

关键字过滤、虚拟滚动、跨会话历史日志原为本节遗留项，已在 FR-10 落地 ✅。

### FR-5 运行地址与端口检测 ✅

- 日志正则解析本地地址（完整 URL 形态 + Vite 7 纯端口形态）；
- Rust 校验监听端口属于本次运行的进程树，再通过 TCP 确认就绪；
- 手动端口兜底；启动前端口冲突预警 toast；
- 同一运行会话的地址可在页面刷新时重新验证；
- 局域网 IP 展示（`get_lan_ip`，手机同 WiFi 访问）。

### FR-6 当前分支显示 ✅

- 读取仓库 Git HEAD（支持仓库子目录和 worktree，不启动 Git 命令）；detached HEAD 显示短哈希；
- 非 Git 目录显示 `-`；
- 刷新时机：手动刷新按钮 + 启动/停止时 + 30s 定时轮询。

未实现（移入 FR-13）：未提交变更小圆点提示（P2）。

### FR-7 设置 🚧

已实现（`settings-dialog.tsx` / `settings.rs`）：

- 全局设置：关闭行为（直接退出 / 最小化到托盘）、开机自启（`tauri-plugin-autostart`）。

未实现（保持待开发）：

- ⏳ 日志行数上限可配置（当前 2000 硬编码）；
- ⏳ 默认包管理器（未识别锁文件时的全局默认值）；
- ⏳「关闭时是否自动停止所有项目」开关（当前为无条件全停）。

### FR-8 批量与其他 ✅（除多脚本、一键 install）

- 批量启动 / 停止 / 重启 / 打开 VSCode / 删除（多选 Checkbox + 工具栏）；

### FR-12 多脚本支持（P1）

日常一个项目常需 dev + mock server + storybook 等多个脚本并行跑。

- **数据模型** ⏳：`Project.script: string` 扩展为 `scripts: { id, name, script }[]`（迁移：旧数据自动包装为单脚本）；兼容读取旧 `projects.json`；
- **UI** ⏳：编辑对话框可增删多条脚本；列表操作列展示脚本启动入口（单脚本保持现状不增加复杂度）；
- **成组控制** ⏳：项目级启动 = 启动该项目的默认脚本或全部勾选脚本；停止仍按项目整组停止（复用进程树 kill）；重启同理；
- **日志** ⏳：多脚本日志合并进同一抽屉，行前缀标注脚本名（如 `[mock]`）；
- **端口解析** ⏳：每条日志行归属到产生它的脚本，多端口分别解析展示。

### FR-20 本地发布流水线 ✅

- **项目配置**：发布分支、完整 Node 版本、构建脚本、产物目录（默认 dist）、预检忽略路径。
- **预检**：从发布分支的已提交文件读取版本基准，展示当前分支和阻塞文件。允许仅有 allowBuilds 变化的工作区，弹窗展示项目级规则差异。
- **执行**：Rust 同时只运行一个发布任务。验证指定 Node 后切到发布分支、复核版本基准并升版本，再用指定 Node 子进程执行构建。
- **产物**：校验构建前后是否有新文件或文件被更新，支持扁平产物和本轮构建的版本目录。ZIP 写入完成后才使用正式文件名。
- **失败恢复**：构建或压缩失败后尝试恢复应用刚写入的版本。构建进程使用独立的 Node 路径，应用保留发布分支供用户检查。
- **发布历史**：最近 100 次发布记录含项目、版本、分支、提交、耗时、结果、日志和产物路径。

### FR-21 启动方案 ✅

- 保存常用项目组合，支持编辑、删除、一键启动和停止，打开时选中上次使用的方案。

### 6.3 关键交互流

**启动流程**（现状，FR-11 落地后在第 1 步前加依赖预检）：

1. 点击「启动」→ 按钮进入 loading，状态 `starting`；
2. 后端 spawn 进程，开始转发日志事件；
3. 前端从日志解析出端口 → 探测连通 → 状态 `running`，地址列变为可点链接；
4. 10s 内未解析到端口但进程仍存活：保持 `running`（按进程存活判断），地址显示「未识别」；
5. 进程启动即退出（脚本报错）：状态 `error`，自动弹出日志抽屉。

**停止流程**（现状）：

1. 点击「停止」→ 按钮 loading；
2. 后端 kill 进程树 → 收到退出事件 → 状态 `stopped`；
3. 3s 未退出：升级为强制 kill（`taskkill /T /F`），toast 提示「已强制结束」。

**安装依赖流程**（FR-11 规划）：

1. 点「安装依赖」→ 若 `node_modules` 已存在，toast 询问是否重装；
2. spawn install 命令 → 日志抽屉自动打开并实时输出；
3. 退出码 0 → toast 成功；非 0 → `error` 样式提示 + 抽屉保留报错。

## 8. 技术方案

### 8.1 总体架构（现状）

- **前端**：React + TypeScript + Vite + Tailwind + shadcn/ui；状态管理 zustand（`projectsStore` 持久化数据、`runtimeStore` 运行时状态与日志缓冲）；
- **后端**：Tauri 2（Rust）承担进程生命周期、文件读写、Git 分支读取、端口探测；
- **通信**：`invoke`（命令）请求-响应；`emit`/`listen`（事件）日志流与状态推送。

现有 Rust 命令：`load_projects`、`save_projects`、`inspect_project`、`read_git_branch`、`scan_projects`、`check_deps`、`read_log_tail`、`start_project`、`stop_project`、`install_project`、`stop_install`、`get_running`、`probe_port`、`get_lan_ip`、`open_in_vscode`、`load_settings`、`save_settings`。

### 8.3 新功能技术要点（规划）

| 功能 | 要点 |
|---|---|
| FR-10 日志落盘 | Rust 侧追加写 `appDataDir/logs/<id>.log`，定期截断只留尾部 N 行；前端打开抽屉时 invoke 读取 |
| FR-11 install | 完全复用 `start_project` 的 spawn 框架，新增命令 `install_project`，日志事件复用（带脚本名前缀） |
| FR-12 多脚本 | `process_manager` pid 表从 `projectId → pid` 改为 `projectId → [scriptId → pid]`；`stop_project` 仍按项目整组 kill |
| FR-14 端口反查 | Rust 执行 `netstat -ano -p tcp` 解析 LISTENING 行；pid → 命令行需 WMI 查询（`wmic process get processid,commandline` 或 `sysinfo` crate） |
| FR-15 资源采集 | 定时轮询 pid 资源；方案二选一（见开放问题 3） |
| FR-16 时长统计 | `appDataDir/usage.json` 记录 `{date, projectId, startedAt, stoppedAt}[]`，启动/停止事件时追加 |

### 8.4 进程管理（已验证的既有方案，新功能继续沿用）

Windows 上 `npm run dev` 是一棵进程树：`npm.cmd (cmd.exe)` → `node (npm)` → `node (vite/next)`。只 kill 最外层会留孤儿 node 进程占端口。现有方案：

- spawn 与 kill 统一在 **Rust 侧**管理（pid 表集中在 `process_manager.rs`）；
- 停止执行 `taskkill /PID <pid> /T /F`；
- 应用退出监听 `RunEvent::ExitRequested` 全量清理；
- 启动时按 `running-pids.json` 清理崩溃残留。

FR-12 多脚本改造时不得破坏以上四点（验收标准 7 需在多脚本场景复测）。

### 8.5 事件流（现状）

```
Rust spawn ──(log-line 事件, 含 projectId)──▶ 前端日志缓冲 + 端口正则解析
        └──(process-exit 事件, 含 code)──▶ runtimeStore 更新状态
前端 invoke:start(projectId) / stop(projectId) ──▶ Rust 命令
```

FR-12 落地后 `log-line` 事件需增加 `scriptId` 字段（向后兼容：缺省归入默认脚本）。

## 9. 边界与异常场景

| 场景 | 预期行为 | 状态 |
|---|---|---|
| 启动脚本报错立即退出 | 状态 `error`，自动弹出日志抽屉，展示退出码 | ✅ |

| `package.json` 缺失 | 添加时校验拒绝，提示「不是有效的前端项目」 | ✅ |
| 应用启动时上次有项目在跑（异常退出残留） | 检测并提示清理孤儿进程 | ✅ |
| 日志爆炸（watch 模式高频输出） | 2000 行环形缓冲；虚拟滚动 | ✅ |
| 同一项目重复点击启动 | 按钮置灰 + runtimeStore 幂等保护 | ✅ |
| install 中途取消/失败 | 手动终止 → toast「已终止安装」不误报失败；退出码非 0 → toast + 自动弹日志抽屉；下次启动重新预检不缓存 | ✅ |
| 多脚本场景下其中一条脚本崩溃 | 该脚本状态 `error` 并弹日志（标注脚本名），其余脚本不受影响 | ⏳ FR-12 |

| 发布时工作区有未提交变更 | 弹窗列出文件并禁用开始；流水线预检同样中止。`.env.development`、项目配置的忽略项、以及只有 allowBuilds 变化的 `pnpm-workspace.yaml` 不算。不自动 stash | ⏳ FR-20 |
| 发布中途失败（build 报错等） | 版本号自动还原为发布前的值，弹窗标注失败步骤并提供重试；Git 分支保留；Node 仅对子进程生效 | ⏳ FR-20 |

| 所需 Node 版本未安装 | 准备构建环境步骤失败，提示安装目标版本 | ✅ FR-20 |
| 弹窗确认的版本基准与流水线实际读到的不同（弹窗打开后分支被更新过） | checkout 后 bump 前校验，不符则中止并提示「版本已变化，请关弹窗重新确认」，不默默发布错误版本号 | ⏳ FR-20 |

## 10. 非功能需求

- **可靠性（最高优先级）**：任何路径下（正常停止、应用崩溃、系统重启、多脚本部分失败）不允许留下孤儿 node 进程 / 被占端口；进程真实状态与 UI 展示状态必须一致；
- **性能**：点击启动到命令下发 < 1s；日志事件到 UI 渲染延迟 < 100ms；列表加载 < 500ms（20 个项目以内）；资源轮询不得影响主进程（后台线程 + 批量事件推送）；
- **安全**：Tauri shell 权能白名单严格限定（只允许配置的包管理器命令），不做通用终端；FR-14 的 netstat/WMI 查询只读；
- **数据**：全部本地（appDataDir），无任何网络上报（FR-18 的 HTTP 探活只请求 localhost 运行地址）；
- **可维护性**：前端 TS 全量类型，Rust 侧进程管理集中在 `process_manager.rs` 单模块。
